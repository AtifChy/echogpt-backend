# EchoGPT Backend

Backend REST API for the EchoGPT Chrome extension.

## Stack

- NestJS 12
- TypeScript 6
- Prisma ORM 8 contract-first API
- PostgreSQL
- Prisma Composer for local infrastructure and optional deployment
- Bun
- `tsdown`

This project was generated by the Prisma NestJS template. Keep its Prisma 8 contract workflow instead of adding the older `schema.prisma`, Prisma Client generation, or `prisma migrate dev` workflow.

## Requirements

- Bun 1.4+
- Node.js 22.18+ or 24.11+
- Git

PostgreSQL 15+ is required. On Windows, use the included Docker Compose database because Prisma Composer local development does not currently support Windows.

## Install

```bash
bun install
```

## Run locally on Windows — recommended

Copy the environment file, start PostgreSQL, initialize the fresh database, and run Nest directly:

```powershell
Copy-Item .env.example .env
bun run db:up
bun run db:init
bun run dev
```

`src/prisma/db.ts` automatically uses `DATABASE_URL` when no Composer database binding is available.

On later starts, the database is already initialized:

```bash
bun run db:up
bun run dev
```

Stop the database without deleting its named volume:

```bash
bun run db:down
```

Do not add `-v` unless you intentionally want to erase the local database.

The generated starter currently exposes:

- `GET /` — starter message
- `GET /users` — seeded sample users

These routes are temporary. The roadmap replaces them with the EchoGPT health, authentication, profile, provider, chat, search, subscription, and admin APIs.

## Composer development on macOS/Linux

Prisma Composer can provision its local database and run the composed application on supported platforms:

```bash
bun run dev:composer
```

This command currently fails on Windows with `DEV.PLATFORM_UNSUPPORTED`. The Docker workflow above is the Windows replacement.

## Run with another PostgreSQL server

Set its connection string in `.env`, then initialize and run directly:

```bash
bun run db:init
bun run dev
```

Never commit `.env`.

## Build and start

```bash
bun run build
bun run start
```

## Prisma 8 workflow

The editable data contract is:

```text
src/prisma/contract.prisma
```

Generated artifacts—commit both after every contract change:

```text
src/prisma/contract.json
src/prisma/contract.d.ts
```

For every database change:

```bash
# 1. Edit src/prisma/contract.prisma
bun run contract:emit

# 2. Create a reviewable migration package
bun run migration:plan -- --name describe-the-change

# 3. Inspect the migration
bun run migration:show

# 4. Direct DATABASE_URL mode only: preview and apply it
bun run migrate -- --show
bun run migrate
```

When using supported Composer local development, Composer applies the committed contract and migrations to its local database. On Windows, apply migrations to the Docker database with `bun run migrate`.

Do not edit these generated files manually:

- `src/prisma/contract.json`
- `src/prisma/contract.d.ts`
- `migrations/**/ops.json`
- `migrations/**/migration.json`

## Development approach

Prefer ordinary Nest feature modules:

```text
src/
├── common/
├── auth/
├── users/
├── subscriptions/
├── providers/
├── chat/
├── search/
├── admin/
├── health/
├── prisma/
├── prisma.service.ts
├── app.module.ts
└── main.ts
```

Each feature should normally contain only a module, controller, service, and DTO folder. Services may query `PrismaService.db` directly. Add repository or domain layers only when a real maintenance problem justifies them.

## Deployment

Deployment is optional while developing. When the API is complete:

```bash
bunx prisma auth login
bun run deploy
```

The generated deployment uses Prisma Composer, Prisma Postgres, and Prisma Compute. You may use another hosting provider instead if required.

## Security rules

- Never commit `.env`, JWT secrets, refresh tokens, encryption keys, or provider API keys.
- Store password and refresh-token hashes, not plaintext values.
- Encrypt stored provider keys with authenticated encryption.
- Do not log full prompts, responses, tokens, or credentials.
- Public registration must never accept an admin role.
